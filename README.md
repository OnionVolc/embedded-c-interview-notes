## 一、内存管理

> 复习碎碎念：申请内存的时候潇洒得像发工资，释放内存的时候失忆得像没这回事。先把“谁申请、谁释放、活多久”讲清楚，别让内存泄漏替我们回答追问。

### 1、谈谈你对内存管理的理解？为什么需要进行内存管理？

内存管理是对程序运行过程中内存资源的分配、使用和释放进行管理，目的是合理利用有限的内存资源，提高程序运行的稳定性和可靠性。
内存管理主要包括两个方面：
第一是**内存区域的划分和管理**。程序运行时的内存通常可以分为代码段、只读数据段、已初始化数据段、未初始化数据段、栈区和堆区，不同区域存放不同类型的数据。
第二是**内存资源的分配和释放方式**。主要包括自动管理和手动管理。例如栈空间通常由系统自动管理，而堆空间需要程序员通过 `malloc `和 `free `进行申请和释放。
之所以需要管理，是因为**内存是稀缺、有限的资源**，需要合理分配，这样可以提高内存的利用率，保证程序的稳定性。

### 2、内存管理有哪些方式？自动管理和手动管理各有什么优缺点？

内存管理方式主要分为两种：手动管理和自动管理。
**自动管理**指的是由系统或者运行环境负责内存的申请和释放，例如栈变量由系统自动分配和释放，C++ 中也可以通过 RAII 和智能指针实现自动释放。它的优点是使用方便，安全性较高，可以减少内存泄漏和野指针问题。但是它的回收机制也带来了开销较大的问题
**手动管理**指的是内存的申请和释放都由程序员自己负责，典型代表就是 C 语言的 `malloc/free`，C++ 的 `new/delete` 。它的好处就是灵活性强，需要多少就申请多少，而且没有额外的回收机制，运行开销小，缺点是需要开发人员负责管理生命周期，如果处理不当容易出现内存泄漏、重复释放和野指针问题。
在嵌入式开发中，由于**MCU 的 RAM 资源有限**，并且很多场景**对实时性要求较高**，所以通常更倾向于**静态分配**，或者谨慎使用动态内存，以保证系统稳定性和实时性。

### 3、程序运行时的内存通常划分为哪些区域？为什么需要这样划分？

- **代码段**主要存放程序指令，在嵌入式系统中通常存放在 Flash 中。
- **只读数据段**主要存放字符串常量和一些具有静态生命周期的只读数据。
- **已初始化数据段**用于存放已经初始化的全局变量和静态变量，程序启动时初始值通常从 Flash 加载到 RAM 中。
- **未初始化数据段**用于存放未初始化或者初始化为 0 的全局变量和静态变量，启动时系统会自动清零。
- **堆区**主要用于动态内存分配，例如 malloc 申请的空间，由程序员负责申请和释放，使用灵活但是容易产生内存泄漏和碎片问题。
- **栈区**主要存放局部变量、函数参数以及函数调用现场，由系统自动管理，分配和释放速度较快，但是空间有限。

划分原因：
因为不同类型的数据在**生命周期、读写权限和分配方式**上存在差异。通过划分不同区域，可以采用不同的存储和管理方式，例如将程序代码放在 Flash 中，将需要修改的数据放在 RAM 中，从而合理利用存储资源，并方便程序初始化和运行。

> ***追问：为什么全局变量初始化值存放在 Flash，运行时却在 RAM？***
> *因为 Flash 掉电数据不丢失，适合保存程序和变量的初始值，而 RAM 具有更快的读写速度，程序运行过程中需要频繁访问和修改变量。*
> *以 STM32 为例，编译时会把已经初始化的全局变量和静态变量放到 **`.data`** 段中，初始值存放在 Flash 中。系统上电启动后，启动代码会将这些初始值从 Flash 复制到 RAM 对应的位置，之后程序运行时访问的是 RAM 中的数据。*

### 4、栈和堆有什么区别？什么时候使用栈，什么时候使用堆？

**栈**通常由编译器和系统自动管理，用于存放函数运行过程中的临时数据，比如局部变量、函数参数、返回地址、函数调用现场等，栈的分配和释放速度快，但是空间有限，如果局部变量过大或者递归层次过深，可能导致栈溢出。
**堆**主要用于动态内存分配，由程序员手动管理，生命周期更加灵活，可以根据运行需求申请不同大小的空间，但是管理成本更高，容易出现内存泄漏、重复释放和内存碎片等问题。
如果数据较小、生命周期短，通常使用栈；如果数据大小或生命周期需要灵活调整，则可以考虑使用堆。

### 5、`malloc`、`calloc`、`realloc` 和 `free` 有什么区别？使用时需要注意什么？

- `malloc` 用于申请指定大小的连续内存空间，但是不会初始化，申请后的内容是不确定的。
- `calloc` 用于申请多个元素的连续空间，并且会将申请的内存初始化为 0。
- `realloc` 用于调整已经申请的内存大小。如果原空间后面有足够空间，会直接扩展；如果空间不足，则可能重新申请新的空间，将原数据复制过去，然后释放旧空间。
- `free` 用于释放动态申请的内存。释放后原要将指针置为 `NULL`。

注意事项：

- 申请内存后要检查返回值，避免申请失败后直接使用空指针
- 使用 `realloc` 时，应先用临时指针保存返回值，避免申请失败导致原指针丢失
- 申请的内存使用结束后要及时释放，释放后指针要置空

### 6、常见内存错误有哪些？

主要包括内存泄漏、野指针、悬空指针、越界访问、重复释放以及使用未初始化内存等。在实际开发中，需要通过规范管理内存生命周期、检查申请结果、释放后置 NULL、避免越界访问等方式减少这些问题。

- **内存泄漏**：申请的内存没有及时释放，导致这部分内存一直被占用，但是程序已经无法访问它。
- **内存越界访问**：访问超过申请范围的内存。包括数组越界、缓冲区溢出、堆溢出、栈溢出。
- **野指针**：指针变量没有初始化，指向未知地址。
- **悬空指针**：指针原来指向一块有效内存，但是这块内存已经被释放，指针仍然保存旧地址。
- **重复释放**：同一块内存释放多次。

### 7、内存泄漏通常由什么原因导致？如何检测、定位和避免内存泄漏？

内存泄漏通常是由于动态申请的内存没有正确释放导致的。常见原因包括申请后忘记释放、函数提前 `return`导致释放代码没有执行、指针被重新赋值导致原来的内存无法释、释放不完整等。
检测方面，可以通过代码检查，或者使用 Valgrind、GCC 支持的内存检测工具来发现问题，并根据调用栈定位泄漏位置。在嵌入式系统中，还可以监测剩余堆空间和内存申请释放情况，辅助排查。
避免方法：
动态申请的内存使用完成后及时释放
明确谁负责管理和释放内存，避免遗漏
确保函数提前返回或发生错误时，已经申请的内存也能得到释放
嵌入式系统 RAM 资源有限，尽量优先使用静态分配，必要时可以使用内存池

### 8、什么是内存池？为什么需要使用内存池？

内存池是一种内存管理技术，核心思想是**提前申请一大块内存，然后将其划分为多个内存块**，程序需要内存时直接从内存池中获取，使用结束后再归还给内存池，而不是频繁调用 malloc 和 free。
原因：

- 提高内存分配效率：普通的 `malloc` 需要查找合适的空闲内存块，而内存池提前组织好可用内存，分配和回收通常更快。
- 减少内存碎片：频繁申请和释放不同大小的内存，容易产生内存碎片。内存池可以通过固定大小的内存块等方式减少外部碎片。
- 提高系统实时性：普通动态内存分配的执行时间可能不确定，而固定块内存池通常可以实现较稳定的分配和释放时间，更适合实时性要求较高的嵌入式系统。

不过，内存池也存在局限，例如需要提前预留空间，固定大小的内存块可能造成内部空间浪费，内存池用尽后也会申请失败。因此，内存池比较适合**频繁申请和释放内存、数据块大小相对固定、对实时性要求较高**的嵌入式场景。

### 9、指针跟数组的区别

本质不同。数组是一组相同类型元素的连续内存空间，创建后大小固定；指针是保存内存地址的变量，可以指向不同的内存区域。
使用方式不同。数组名不能像指针变量一样重新赋值或自增，而指针变量可以改变指向。数组和指针都可以通过下标或者指针运算访问元素。
sizeof 的结果不同。 对实际数组使用 sizeof，得到的是整个数组的大小；对指针变量使用 sizeof，得到的是指针本身的大小。
安全性不同。数组和指针都可能发生越界访问，但指针还需要特别注意野指针、悬空指针等问题。如果通过指针管理动态分配的内存，还需要防止内存泄漏、重复释放和释放后继续使用。

### 10、使用指针时，常见的内存安全问题有哪些？如何避免？

使用指针时，常见的内存安全问题主要包括：空指针解引用、野指针、悬空指针、内存越界、内存泄漏和重复释放。
避免：定义指针时立即初始化、使用前判空、释放后立即置空、使用指针访问数组或缓冲区前进行边界检查。

### 11、在嵌入式开发中，如何合理选择内存分配方式？

- **静态分配。** 对于大小固定、需要长期存在的数据，优先使用全局变量或静态变量，例如串口 DMA 接收缓冲区，避免运行时频繁申请内存
- **栈分配。** 对于生命周期较短、占用空间较小的临时变量，优先使用栈空间，分配和释放效率较高，但需要注意栈溢出
- **动态分配。** 对于大小或生命周期需要灵活调整的数据，可以考虑动态分配，但要避免频繁调用 `malloc/free`。如果需要频繁申请和释放固定大小的内存块，可以采用内存池，减少内存碎片，提高分配时间的可预测性。

### 12、如果让你设计 STM32 的内存管理方案，你会怎么选择？

如果让我设计 STM32 的内存管理方案，我会根据芯片的 RAM 容量、程序的实际需求以及实时性要求，采用**静态分配为主、栈分配为辅、动态分配尽量少用**的方案。
首先查看 STM32 的 Flash 和 SRAM 容量，明确程序代码、全局变量、栈和堆分别需要多少空间。对于大小固定、需要长期使用的数据，我会优先使用全局数组或者静态数组。对于函数内部的临时变量，我会使用栈分配。如果确实存在运行时才知道数据大小的情况，我会考虑使用动态分配，比如使用内存池，减少内存碎片。
## 二、关键字

> 复习碎碎念：这几个关键字，代码里天天见，面试时一问区别，嘴巴突然就进入低功耗模式了。挨个拆开，再把容易混的放一起比较，争取开口的时候顺利唤醒。

### 1、`static` 关键字有什么作用？

主要有两个作用：一个是延长局部变量生命周期，另一个是限制全局变量和函数的链接属性
`static` 修饰局部变量时，变量的生命周期会延长到整个程序运行期间，但作用域不变。而且只会初始化一次，能够在多次函数调用之间保留上一次的值。
之所以使用静态局部变量，是因为全局变量可以被多个函数访问和修改，如果使用不当，就容易造成数据被意外修改，增加程序的维护难度。
`static` 修饰全局变量和函数，他们就只能在当前源文件中通过名称访问，不能被外部访问。这样做主要是为了解决实际工程中，多人合作开发时命名冲突和模块耦合的问题。

### 2、`extern` 关键字有什么作用？

主要用于**声明**在其他位置定义的全局变量或函数，使不同源文件之间能够共享这些变量和函数。 `extern` 声明本身通常不会分配新的内存空间，它只是告诉编译器这个变量已经在其他地方定义了。
因为实际开发通常采用多文件编程，不同模块之间有时需要共享变量或者函数，所以需要通过 `extern` 实现外部访问，实现跨文件引用。

### 3、`const` 关键字有什么作用？有哪些使用场景？

主要用于限定数据的修改权限，防止程序中的数据被意外修改，提高代码的安全性和可维护性。
在实际开发中，`const` 可以用于修饰不希望被修改的变量，也可以修饰指针，限制通过指针修改数据，或者限制指针本身的指向。`const` 在实际工程中的主要价值，就是明确数据的读写权限，减少意外修改，提高程序的可靠性。

### 4、`volatile` 关键字有什么作用？为什么嵌入式开发经常使用它？

告诉编译器，该变量可能会被程序运行之外的因素改变，所以每次访问都要从内存读取，不能优化、合并、缓存到寄存器里。
在嵌入式开发中，我们常常用`volatile` 来访问硬件寄存器和修饰中断与主程序之间的共享变量。因为有些寄存器的值会随着外设状态发生变化，并且当中断服务函数负责修改一个标志位，而主循环需要不断检测这个标志位的时候，编译器可能会把循环中的读取操作优化掉，导致主循环无法及时发现标志位的变化。

### 5、`volatile` 和其他关键字的搭配，为什么这样搭配？通常用在什么场景下？

在嵌入式开发中，`volatile` 经常会和 `const`、`static`、`extern` 等关键字配合使用。

- `const volatile`：程序只允许读取，但数据可能被硬件修改，常用于**只读硬件状态寄存器**。
- `static volatile`：变量可能被中断修改，同时不希望它被其他源文件通过名称直接访问，常用于**模块内部的中断标志位**。
- `extern volatile`：其他源文件需要访问某个可能被硬件或中断修改的全局变量，常用于**跨文件共享状态**。

### 6、`register` 关键字有什么作用？

主要用于**建议**编译器将变量存放在 CPU 寄存器中，而不是内存中，从而减少内存访问，提高程序的执行效率。`register` 只是给编译器的一个优化建议，并不能保证变量一定会存放在寄存器中
之所以需要 `register`，是因为 CPU 访问寄存器通常比访问内存更快。如果一个变量需要被频繁使用，比如循环计数器或者一些临时计算变量，就可以使用 `register` 修饰。不过，现代编译器已经具有寄存器分配和优化能力，所以在实际嵌入式开发中，我们只需要交给编译器进行优化。

### 7、`typedef` 有什么作用？它和 `#define` 有什么区别？

用于给已有的数据类型**起别名**，它不会创建新的数据类型，而是通过类型别名来提高代码的可读性和可维护性。比如在嵌入式开发中， `uint8_t`、`uint32_t` 就是通过 `typedef` 定义的。
`typedef` 是由**编译**器给已有的数据类型起别名，而 `#define` 是在**预处理**阶段进行简单的文本替换。`typedef` 只能用于定义类型别名，编译器会**进行类型检查**；而 `#define` 的用途更加广泛，可以定义宏常量、宏函数等等，但它本身只是文本替换，**不进行类型检查**。

### 8、`#define` 有什么作用？宏函数和普通函数有什么区别？

主要用于定义宏常量和宏函数，它的核心特点是在预处理阶段进行文本替换。主要是为了减少重复代码，提高程序的可读性和可维护性。
**宏函数**是在预处理阶段进行文本替换，不会产生宏本身的函数调用，因此可以避免相应的函数调用开销。但是宏函数没有独立的参数类型检查，而且参数可能被重复求值，容易产生副作用，可维护性差。
**普通函数**是在程序运行时执行函数调用，编译器会进行参数类型检查，执行过程更加规范，也更容易调试和维护。不过，普通函数可能存在一定的调用开销。
所以在实际开发中，如果只是进行简单的宏替换，可以使用宏函数；如果需要封装逻辑、保证类型安全，我通常会优先选择普通函数，对于简单且频繁调用的函数，还可以考虑使用 `static inline` 内联函数。
## 三、用户自定义类型

> 复习碎碎念：结构体负责组队，共用体负责合租，枚举负责贴标签。脑子里先有个画面，别一上来就和 `sizeof` 互相折磨。

### 1、什么是结构体？为什么需要结构体？它主要解决什么问题？

结构体是一种**用户自定义数据类型**，它可以将多个不同类型的数据组合在一起，形成一个整体进行管理和使用，结构体的各个成员拥有独立的存储空间。在实际开发中，我们可以使用结构体实现类似面向对象的**封装**思想，一是可以封装数据，二是可以封装数据和操作，来提高代码的可维护性和扩展性。

### 2、C 语言如何通过结构体和函数指针实现封装？

具体来说，结构体主要用于封装数据，函数指针用于关联操作这些数据的函数。这样设计的好处是降低模块之间的耦合，提高代码的可维护性和可扩展性。
```c++
typedef struct{
    int status;                  // 设备状态
    void (*init)(void);          // 初始化函数
    int (*read)(void);           // 读取数据函数
} Device;
```

### 3、什么是共用体？为什么需要共用体？它主要解决什么问题？

共用体也是一种**自定义数据类型**，它和结构体最大的区别在于，结构体的各个成员分别占用存储空间，而共用体的所有成员共享同一块内存空间。之所以需要共用体，主要是为了**节省内存空间，提高内存的利用率**。
在实际开发中，有些数据并不需要同时存在，而是根据不同的业务场景，可能表现为不同的数据类型。因此，我们可以使用共用体，让不同类型的数据共享一块内存，在不同情况下使用对应的成员。
```c++
union Data {
    int a;
    float b;
    char c;
};

union Data data;

data.a = 100;
data.b = 3.14f;
```

### 4、结构体和共用体有什么区别？

在**内存分配**方面，结构体的每个成员都有各自独立的存储空间，它的大小通常是所有成员大小，再考虑内存对齐填充因此可以同时保存所有成员的数据。而共用体的所有成员共享同一块内存空间，同一时间只能保存其中一个成员的有效值，它的大小主要由占用空间最大的成员决定，再考虑内存对齐。
在**使用场景**方面，结构体主要用于将多个相关的数据组织在一起，实现数据的统一管理和封装；而共用体主要用于多个数据不需要同时存在的情况，通过复用内存空间来减少内存占用。

### 5、什么是内存对齐？为什么结构体需要内存对齐？

内存对齐是指数据在内存中存放时，需要按照一定的字节边界进行排列。比如一个 int 型变量，通常要求它的起始地址是 4 的整数倍。内存对齐主要是为了提高CPU的访问效率。在实际嵌入式开发中，我们可以通过合理调整结构体成员的排列顺序，减少不必要的填充字节，从而节省内存空间。

### 6、结构体的大小如何计算？为什么 sizeof 结构体可能大于成员大小之和？

结构体中，每个成员的起始地址通常要是自身对齐字节数的整数倍，结构体整体按最大的成员对齐要求进行对齐，最终总大小也要是该对齐值的整数倍，不足的部分通过填充字节补齐。
sizeof 计算的是结构体实际占用的总字节数，包括**成员本身的大小和填充字节**，所以结果可能大于所有成员大小之和。

### 7、枚举有什么作用？为什么需要使用枚举？

枚举是一种用户自定义类型，主要用于将一组具有特定含义的整数常量组织在一起，并通过有意义的名称来表示不同的状态或者选项。
我们可以使用枚举，用具有实际含义的名称代替没有明确含义的数字，让代码更加直观，也方便统一管理这些状态。

### 8、结构体、共用体和枚举如何配合使用？

枚举用于标识当前的数据类型，共用体用于存储不同类型的数据，结构体则将数据类型和实际数据组织在一起。
在实际开发中，有些数据可能存在多种类型，但同一时刻只需要使用其中一种。通过共用体可以节省内存，通过枚举可以判断当前存储的是哪种数据，而结构体可以将它们封装起来，方便统一管理。
```c++
// 第一步：枚举标识数据类型
typedef enum {
    DATA_INT,
    DATA_FLOAT
} DataType;

// 第二步：共用体存储实际数据
typedef union {
    int i;
    float f;
} DataValue;

// 第三步：结构体将二者组织起来
typedef struct {
    DataType type;
    DataValue value;
} Data;

// 第四步：根据枚举类型读取对应数据
Data data;

data.type = DATA_INT;
data.value.i = 100;

// 如果 type == DATA_INT，说明里面是整数，就用 data.value.i 读；
// 如果 type == DATA_FLOAT，就应该用 data.value.f 读。
if (data.type == DATA_INT) {
    printf("%d\n", data.value.i);
}
```
## 四、位运算

> 复习碎碎念：位运算写对了叫精准控制，写错了就开始怀疑板子是不是焊坏了。先把掩码看明白，少让开发板替代码背锅。

### 1、什么是位运算？为什么嵌入式开发经常使用位运算？

位运算就是直接对二进制位进行操作的运算。常见的位运算包括按位与、按位或、按位异或、按位取反以及左移和右移。
嵌入式开发经常使用位运算，最主要的原因是硬件寄存器通常以二进制位来定义功能，需要通过位运算进行精确控制。

### 2、C 语言有哪些常见的位运算符？分别有什么作用？

- 按位与（`&`）：有零则零，通常用于清零（取反与）。
- 按位或（`|`）：有一则一，通常用于置 1。
- 按位异或（`^`）：相异为 1，相同为 0，通常用于翻转。
- 按位取反（`~`）：0 变 1，1 变成 0，通常配合按位与操作清零。
- 左移（`<<`）：将二进制位向左移动指定的位数，右侧补 0。
- 右移（`>>`）：将二进制位向右移动指定的位数。对于无符号整数，右移时左侧补 0。

`&`和`~`搭配通常用于判断和清除某一位，`|`用于置位，`^`用于翻转，`<<`常用于生成位掩码，`>>`常用于提取指定的数据位。

### 3、什么是位掩码？为什么需要使用位掩码？

位掩码就是一个用来定位二进制位的数。它的某一位是 1，就表示要操作或关注这一位；是 0 就表示不影响或屏蔽这一位。
之所以需要位掩码，主要是为了精确控制或提取指定的二进制位，同时尽量不影响其他位的数据。

### 4、如何使用位运算实现某一位的置位、清零、翻转和状态检测？

- 置位 `data |= (1U << 3);` 第 3 位置为 1
- 清零 `data &= ~(1U << 3);` 第 3 位清为 0
- 翻转 `data ^= (1U << 3);` 第 3 位的 0 和 1 互换
- 状态检测 `data & (1U << 3)` 判断第 3 位是否为 1

### 5、左移和右移运算有什么作用？与乘除法有什么关系？

左移和右移主要用于对整数的二进制位进行移动。对于**无符号整数**，在没有高位丢失的情况下，左移 n 位相当于乘以 `2^n`，而右移 n 位相当于除以 `2^n`，并舍去余数。
在嵌入式开发中，移位运算不仅可以用于部分数值计算，更重要的是生成位掩码、操作寄存器以及提取和组合通信数据。

### 6、在 STM32 开发中，如何通过位运算操作硬件寄存器？

在 STM32 开发中，硬件寄存器通常通过不同的二进制位来控制外设功能，所以我们可以使用位运算，对寄存器中的指定位进行操作。
具体来说，首先通过寄存器地址访问对应的寄存器，然后使用位掩码配合按位或、按位与、按位异或等操作，实现指定控制位的置位、清零、翻转以及状态读取。
